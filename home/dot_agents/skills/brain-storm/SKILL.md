# brain-storm

Facilitate an interactive brainstorming session. Your job is to be a thinking partner — draw ideas out of the user, push past the obvious, and leave them with an organized set of options and a clear next step. Favor breadth first, then converge.

## When to use

The user says things like "help me brainstorm…", "I have an idea for…", "what are some ways to…", "I'm stuck on…", or "let's think through…". Use it for product ideas, feature directions, naming, content angles, problem-solving, business strategy — any open-ended ideation.

## Process

Run these phases in order. Keep momentum — don't interrogate the user with a long questionnaire up front.

### 1. Frame the problem (briefly)

Restate the topic in one sentence and confirm you've understood it. Ask **at most 2–3** sharp questions only if the framing is genuinely ambiguous — otherwise proceed. Worth knowing:

- **Goal**: what does a good outcome look like?
- **Constraints**: budget, time, audience, must-haves, non-negotiables.
- **Stage**: blank slate, or refining something that already exists?

If the user is vague, pick a reasonable interpretation, state it, and start generating. Producing ideas is more useful than gathering requirements.

### 2. Diverge — generate widely

Produce a broad spread of ideas. Aim for **8–15** to start. Optimize for variety, not polish — explicitly include some safe ideas, some ambitious ones, and 1–2 deliberately unconventional ones. Use these lenses to break out of the obvious and avoid a monotone list:

- **Analogies**: how do other industries/products solve a similar problem?
- **Inversion**: what would the opposite or worst approach look like? Flip it.
- **Constraints**: what if it had to be free? 10x bigger? built in a weekend?
- **Combination**: mash two unrelated ideas together.
- **First principles**: strip the problem to its core need and rebuild.
- **Personas**: how would a specific user, a competitor, or a skeptic approach it?

Present ideas as a scannable list with a short bold label and a one-line description each. Don't over-explain in this phase.

### 3. Expand — go deeper on what resonates

Ask the user which 2–4 ideas they want to develop (or pick the strongest yourself if they defer). For each:

- Sketch how it could work concretely.
- Note the upside, the main risk or open question, and roughly what it would take.
- Suggest one variation or extension.

### 4. Converge — organize and prioritize

Pull the session together into a structured summary:

- Group ideas into themes if there are many.
- Offer a rough prioritization — a simple **impact vs. effort** read, or a clearly labeled top pick with the reasoning.
- Surface any tradeoffs or assumptions worth testing.

### 5. Land on a next step

End with **one concrete, actionable next step** — a prototype to try, a question to validate, a person to talk to, or a decision to make. A brainstorm that doesn't lead to action was just a chat.

## Style

- Be generative and encouraging, but not a hype machine — name real weaknesses in ideas.
- Keep your own turns tight; leave room for the user to react and steer.
- Build on the user's contributions ("yes, and…") rather than replacing them.
- Use formatting (bold labels, short lists, the occasional table) to keep things scannable.
- It's a dialogue. Check in and adjust direction; don't dump a finished report when the user wanted to think out loud.

## Output

A working brainstorm in the conversation, ending with:

1. An organized summary of the strongest ideas (grouped/prioritized).
2. Key tradeoffs or open questions.
3. One concrete recommended next step.
4. Any follow-up skills or actions the user might want to invoke next (e.g. `/grilling` to stress-test an idea, `/sdd` to spec one out).
